## Dynamically generated controls

These are generated by the existing app after import, so they are not counted among the 80 initial ID-bearing controls. Their original containers and handlers remain intact.

| Control family | New location | Verification |
|---|---|---|
| Per-material albedo tint, vertex colours, alpha cutoff, normal-Y flip | Materials and textures → Material texture assignments (`materials`) | Existing material creation/persistence code unchanged; import/texture relationships and project roundtrip tested |
| Per-material Diffuse / Opacity / Normal / Specular assignment and clear action | Same `materials` container | Existing controls and source relationships unchanged; FBX/OBJ/TGA/PNG/JPG tests retained |
| Per-bone anatomical role dropdowns, unmapped state and mapping apply/reset/save/load | Skeleton and animation → Edit source bone mapping (`mapping-editor`) | Actual source-mapping UI integration and 15-row native fixture tested |
| Model list and source animation list | Workflow model selector; Skeleton and animation | Actual two-model switching, source-animation test and project selection roundtrip |
| Mesh classification, facial landmark options and regional allocations | Local corrections; Face and anatomy; Diagnostics | Existing ID-bearing selectors retained; Art Director/profile/project mechanisms unchanged |
| Per-material warnings, validation gate and raw report | Diagnostics | Original message/stat/report nodes retained; native gameplay remains explicitly unverified |

The advanced-panel reveal in the shared automation harness is explicit test convenience for legacy algorithm tests. Production launches default to standard mode; the dedicated UI test exercises that real default, visible navigation, keyboard actions, stored preferences and actual exports.
