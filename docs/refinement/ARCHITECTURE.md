# Phase A architecture and evidence boundaries

Base: regular converter387f008, including the tested beta2 visual-quality checkpoint; no main or beta1 changes. Optional editor only. No new importer or character-specific decision logic.

- refinement.js: mesh IDs, 64-bit-style dual-hash triangle signatures backed by position/UV/skin identity, topology-checked selections, orientation-consistent adjacency, bounded command history and vertex masks. Geometry-version cache. Duplicate triangle identities fail closed. Shared positions alone do not authorize welding.
- refinement-correspondence.js: existing studioSourceMeshIndex and studioRegions.sourceMaterialIndex constrain a lazy SurfaceIndex per original primitive. Posed points are compared in root-relative coordinates independent of preview-holder normalization. Barycentrics, UV channel and skin availability reported. Distance/orientation and equally near unrelated surfaces gate uncertainty. Initial selected-triangle sample only, not a repair correspondence field.
- Existing optimizer consumes local masks. User-selected groups retain their boundary vertices; joined deformation reducers cannot move selected points. Masks/identity-changing collar merging are isolated. Every editor reoptimization starts from the same retained artistic base. Unsupported reductions may exceed budget; no triangles added by protection.
- refinement-editor.js: actual visible-surface raycasts, cutout sampling, selection overlay outside export hierarchy, contextual inspector, proposals/apply/cancel, command toggles and undo/redo. Selection/camera events do not convert. Existing controls remain in the inspector outside refinement mode.
- Optional t3cs-project/1 refinement extension: versioned state plus a single ObjectLoader artistic snapshot asset; existing source assets and CRC checks retained. Snapshot keeps groups, UVs, materials, skin attributes and transforms without a GLB primitive-splitting roundtrip. Readback validates geometry and commands. Reoptimization/rebaking is replayed on reopen. No incompatible schema replacement.
- Actual GLB exports serialize the visible candidate, with descriptive extras. Editor state is fully recoverable from project files, not promised as a cross-editor GLB editing stack. Overlay is excluded. Phase B/C are not exposed as functional buttons.

Memory: artistic geometry must remain alive while an optimized preview exists for non-destructive undo. Textures share image objects during optimizer cloning; overlay copies only selected geometry. Snapshot serialization and baking can temporarily allocate extra buffers. No unmeasured RAM/performance claim. Heavy reducers remain synchronous; cancellation is not advertised as immediate in Phase A.

Synthetic tests cover selection identity/adjacency, unknown and overlapping correspondence, multi-UV channels, bounded history/transaction rollback, actual optimizer effects, skinned vertex preservation, legacy/new projects. Real Electron integration covers screen-space click, overlay, proposal cancellation, optimizer counts, undo/redo/toggle, source immutability, three screen sizes, cold project reopen and independent GLB readback. Synthetic proof is not commercial-model artistic approval or runtime gameplay validation.
